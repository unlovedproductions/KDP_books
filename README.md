# KDP_books

A workspace for producing Amazon KDP paperbacks, where the interiors and covers are generated by code and every book is built from a written specification.

## What is in here

| Folder | What it contains |
|---|---|
| [`Coloring-Books/`](Coloring-Books/) | Two toddler coloring books drawn in code as vector PDFs (interior and cover), with a shared cover library. Setup and build steps are in its README. |
| [`Sudoku-Books/`](Sudoku-Books/) | A large-print Sudoku book for readers with poor vision: puzzle generator (`sudoku.py`), interior and cover generators, and `check_output.py` to check the result before upload. |
| [`Stoic-Collection/`](Stoic-Collection/) | A two-book Stoic series (Book 1: Foundations; Book 2: a Stoic journal). Holds the specifications, manuscripts, KDP listing setup and audit reports. |
| [`research/demand-gap/`](research/demand-gap/) | A fixed-rule method for choosing a niche from fetched KDP listings (`listings.csv`, `listings.schema.json`, and the written `shortlist.md`). |

## How the Stoic Collection is organized

The folders are numbered so it is clear which document wins:

1. `00_MASTER_INSTRUCTIONS` – how the work is to be carried out.
2. `01_SOURCE_OF_TRUTH` – controlling documents: design specification, series bible and architecture, project briefs.
3. `02_APPROVED` – blueprints, manuscripts and listing specs that have been signed off. Approved files are moved here rather than copied, so there is only one current version.
4. `03_WORKING` – drafts and production scripts still in progress.
5. `04_OUTPUT` – audit reports: KDP compliance and presubmit checks, editorial audits and source-verification reports.

Each book also has a `PRODUCTION_LOCKS.md` file that fixes trim size, margins, fonts and spine math, so the generators and the reviews use the same numbers.

## Building a book

You need Python 3, Ghostscript (`gs`) and Poppler (`pdftoppm`). On Debian, Ubuntu or Pop!_OS:

```bash
sudo apt install ghostscript poppler-utils
python3 -m venv .venv && source .venv/bin/activate
pip install -r Coloring-Books/requirements.txt
```

Then follow the build steps in [`Coloring-Books/README.md`](Coloring-Books/README.md). Build the interior first: it writes the page count that the cover generator uses to calculate the spine width.
